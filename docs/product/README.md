## 下一阶段顺序

1. **下载可信度。** 固定数据集比较正常下载、断网/睡眠恢复、过期链接、服务器限流、磁盘不足；记录内容一致性、重复字节、恢复操作数与磁盘峰值。先保证不损坏、不虚报，再比较速度。已完成范围及剩余边界见[单文件偏移存储验证](OFFSET_STORAGE_MIGRATION_2026-09-08.md)，不要把该结果泛化到 HLS 或 yt-dlp。
2. **从浏览器到项目目录。** 改善 Relay 的安装/握手验证，避免没有连接就显示可用；减少认证文件接管和目的地选择的摩擦。是否优先 Safari 由目标用户验证决定。
3. **完整体验。** 以真实下载任务审查宽窄窗口、数千任务、状态反馈、完成动作、键盘路径及动效。当前修复了分段动画比例；下一步重点是首次成功体验和紧凑窗口信息取舍。
4. **证明付费价值。** 用上述真实流程制作可复现演示，再做小规模试用和购买验证；不在旧许可草案上直接开启收费。

“Wow”演示候选：用户从浏览器交接一个重要文件，中断后继续，文件进入正确项目目录并能立即使用。只有实际做得到才演示；不能用动画代替恢复成功。

## 历史与假设

`ELECTRON_PARITY_AUDIT.md` 是旧架构快照；`warm-copper-theme.md` 是未采用的设计探索；`MONETIZATION.md` 的价格和模式是待验证建议。旧检查结果只适用于其记录的版本。逆向规格是行为参考，原版未确认的逻辑不能冒充事实；伪代码也不是获授权可直接发行的开源代码。

# Electron 产品能力差距审计

更新时间：2026-08-15

这份审计对照三处真实实现，而不是把旧界面当作设计模板：

- 当前 Electron 壳层：`src/main`、`src/preload`、`src/renderer`
- 当前 Swift 产品层：`NDM/Sources/NDMApp` 与 `NDM/Sources/NDMCore`
- 原版 NDM 行为记录：`NDM/reverse/specs` 与 `NDM/docs/FEATURE_PARITY.md`

原则：保留成熟能力，重新设计交互；不为了“对等”复制陈旧界面，也不把尚未接线的引擎能力写成 Electron 已支持。

## 已经形成的 Electron 基线

| 能力 | 当前状态 | 备注 |
|---|---|---|
| 大列表、状态/类型筛选、搜索 | 已有 | 虚拟列表；状态切换不再重绘全部任务 |
| 普通 HTTP 与媒体任务的新建 | 已有 | 支持整段分享口令、媒体探测、画质选择和浏览器会话重试 |
| 暂停、继续、重试、删除 | 已有 | 删除文件走废纸篓；底部动作与右键菜单均可达 |
| 连续进度与真实后处理阶段 | 已有 | 下载、合并、字幕、整理共用单调旅程 |
| Quick Look、访达、打开、复制 | 已有 | 已完成文件使用 macOS 能力 |
| 真实缩略图 | 已有 | 下载前使用站点封面；落盘后优先使用系统文件缩略图 |
| 失败诊断与更新链接 | 已有 | 不再显示 `#diag:` 存储串；更新 URL 保留原任务 ID 与断点 |
| 系统分享 | 已有 | 直接使用 macOS Share Menu，不自造网页式分享面板 |
| 通知、Dock 角标与总进度 | 已有 | 由实时任务快照驱动 |
| 基础设置 | 部分 | 下载目录、分类目录、连接数、全局限速、HTTP/SOCKS 代理 |

## P0：用户已经能碰到的能力断层

| 缺口 | 引擎/Swift 状态 | Electron 缺少什么 | 下一步 |
|---|---|---|---|
| 合集下载 | Swift 已有 Collection Lens 和顺序队列 | Host 探测只返回单视频 formats；没有当前项/整合集选择 | 扩展 `probeMedia` 契约，增加合集摘要与范围选择 |
| 字幕、容器与交付偏好 | Swift 已有站点偏好、字幕和 MP4/MKV 选择 | Composer 只有一个 format ID；设置不记站点选择 | 在画质选择中加入渐进式“格式与字幕”，成功后再持久化 |
| 下载前空间把握 | Swift 已有 Space Confidence | Electron 在开始前不显示预计体积、可用空间或合并峰值 | 主进程提供卷空间；Composer 只在风险存在时显示 |
| 重复任务识别 | Swift 已有 Already Here | Electron 会直接创建重复任务 | Host 返回保守匹配结果，界面提供“查看已有 / 再下一份” |
| 过期授权的浏览器接力 | Swift 可打开来源页并自动认领新授权 | Electron 已可手动更新链接，但还没有完整“回来源页继续”闭环 | 将 `pageURL` 与诊断动作接入浏览器 Relay 认领流程 |
| 任务列表与完成结果 | Swift 有 Completion Stack | Electron 只把一个主文件当成果 | Host 输出字幕、封面、音轨和元数据清单；详情内默认折叠 |

## P1：付费级下载管理能力

| 缺口 | 现有基础 | 产品方向 |
|---|---|---|
| 定时下载 | `DownloadTask.startAt`、`DownloadManager.schedule` 已实现 | 用原生日期时间选择语义；等待状态明确写“今晚 23:00 开始” |
| 单任务实时连接数 | 引擎支持运行中重规划 | 详情只显示数量，无法调整；加入紧凑 stepper 并解释智能调节 |
| 单任务限速 | 引擎已有 per-task bandwidth | 详情提供“不限速 / 自定义”，不与全局设置混淆 |
| 诊断解释的完整动作 | 诊断分类已接入 | 为登录失效、限流、磁盘满分别提供正确主操作，而不是统一重试 |
| Smart Finalize | Swift 已有成果命名和原文件/音频配方 | Composer 以“想得到什么”组织，而不是暴露工具参数 |
| 菜单栏迷你面板 | Swift 已有 Agent | Electron 尚无 Tray/Popover；补总速度、最近任务和全部暂停 |
| 拖放入口 | 原版和 Swift 均有 | Electron 主列表还需接受链接、文本文件与浏览器拖放 |

## P2：发行、增长与长周期能力

| 缺口 | 说明 |
|---|---|
| 首次使用引导 | 只保留三步：价值、真实分享口令、隐私；不做功能旅游 |
| 本地扩展安装与商店状态 | 没有正式商店版本时不伪装“官方商店版”；清楚标记本地扩展 |
| 自动更新与站点兼容更新 | Swift 已有签名工具清单能力；Electron 发行壳尚未暴露状态 |
| License / Pro | Swift 有本地 Ed25519 校验；是否迁移取决于真实商店与定价，不先造假购买链 |
| 原版设置补齐 | 登录启动、完成提醒开关、自定义 UA、队列同时/逐个、代理凭据库 |
| 无障碍与降低动态效果 | 所有 motion 与声音都要服从系统 reduce-motion、对比度和静音偏好 |

## 组件采用准则

1. 首选 macOS 原生能力：Quick Look、Share Menu、Finder、系统通知、文件缩略图、日期语义。
2. Web 组件只负责 Electron 真正擅长的高密度动态界面：虚拟列表、上下文菜单、媒体选择、分段进度。
3. 允许采用成熟无头组件库，但视觉 token、键盘行为、焦点、窗口边界和声音必须统一；不拼贴多个设计系统。
4. 装饰不能承担状态含义。状态必须由文字、图标、进度或明确动作解释，不能再出现无说明的彩色竖条。
5. 每个新组件必须有真实数据路径和自动验收；没有数据时隐藏，而不是用假卡片填空。

## 实施顺序

1. 合集 + 字幕/容器选择
2. Space Confidence + Already Here
3. 单任务连接/限速 + 定时下载
4. Completion Stack + Smart Finalize
5. 菜单栏面板、拖放、Onboarding
6. 发行、更新、授权与商店闭环

# 失败状态怎么设计（NDM 桌面端）

这份文件是**规则**，不是阶段汇报。写它是因为一次真实反馈：任务详情里用「红色底 + 红色描边」的圆角框显示「下载地址已失效」，用户直接指出这种处理方式像套模板的 AI 产物，没有设计判断。

结论一句话：**颜色是信号，不是背景。**

## 1. 为什么红色底是坏味道

把错误做成一块染色的面板，是三个问题的叠加：

1. **用面积表达严重程度。** 颜色铺满一块区域，等于宣称「这里出大事了」。但一次下载失败、一次链接过期，只是**一条记录**的局部问题：列表还能用，其他任务还在跑，用户也没有必须立刻处理的义务。用整块红色等于谎报紧急度。
2. **警报疲劳。** 下载器天生会出现失败：源站 403、链接过期、磁盘满。失败是常态而不是意外。常态化的警报色会迅速贬值——用户很快学会无视它，真正需要让步的（磁盘满、引擎不可用）也就失去了区分度。
3. **面板把文字降级。** 染色底一旦出现，视线先落在色块上，真正重要的信息（**发生了什么 / 为什么 / 接下来做什么**）反而变成色块的注脚。

替代方案也不是「全部换成灰色」：那样又丢掉了「这里出问题了」的信号。正确的做法是把颜色**缩小到该缩小的地方**。

## 2. NDM 的失败语法

任何失败、警告、状态提示，都按同一个结构写：

```
⌗ 标记        一个 14px 图标（或 2px 竖线），取语义色
   标题        发生了什么    body / medium / paper
   正文        为什么、怎么办  label / fog
   ─────────  （需要时）hairline 分隔，不用色块
   动作        恢复路径       h-control 按钮，静止色，只有必要的一个用强调色
```

具体到实现：

- **表面**：继续用所在容器自己的表面（详情面板就是 `bg-panel`，列表行就是行本身）。失败块与普通区块唯一的区别是顶部一条 `border-line/60` 细线，和面板里其他小节完全一致。
- **色相**：只落在标记和需要指认的那一小段文字上（`text-clay`），以及必要时的主恢复动作。**不落在背景、不落在边框**。
- **层级**：标题用正文级（13px medium、`text-paper`）说「下载未完成」，说明用 12.5px `text-fog` 说「地址已失效，请打开来源页面」，两者靠字重与颜色分层，不靠色块。
- **结构顺序**：先事实、再原因、最后动作。动作放在讲解之后，用户读完才知道按钮在解决什么。
- **动作**：恢复动作放在面板的常规动作行里（行内一个按钮即可），不要为了「强调」再包一层卡片，也不要同时给出三个等价选项。
- **降级信息**：技术细节（`errorText`）放进「错误详情」折叠，默认收起。

列表行遵守同一条语法：状态列只用一个 11px 图标 + 11.5px 文字承担色相（`失败`、`安装失败`），行的其余部分是中性色。禁止在行上再铺一层红底。

**允许的例外**：真正需要用户立刻决策且会中断流程的地方——确认删除对话框的破坏性按钮、批量删除按钮——可以用实心 `bg-clay/15` 底色。它们是**动作**，不是**状态**；实心只在用户手指已经落在按钮上时出现。

## 3. 自查清单

设计或评审一个失败状态时，依次回答：

1. 去掉颜色后，用户还能读懂发生了什么吗？（若能，色相只是锦上添花。）
2. 色相出现在几个元素上？（标准答案：1 个标记，必要时 + 1 个动作。）
3. 背景有没有被染色？（有就是坏味道。）
4. 有没有为了「醒目」再套一层圆角卡片？（`rounded-surface`/`rounded-lg` 嵌套在面板里就是套卡。）
5. 有没有比它更严重、真正需要打断用户的状态？如果有，两者必须长得明显不同。
6. 文案是否按「事实 → 原因 → 动作」排列？
7. 去掉颜色后，正文与背景的对比度是否仍 ≥ 4.5:1？（`text-fog` 在 `bg-panel` 上满足；不要用 `clay` 承载正文。）

## 4. 落地位置

- 规则所在：`src/renderer/src/index.css`（tokens 上方的 `Failure grammar` 注释）。
- 任务详情失败块：`Inspector.tsx` 的 `[data-download-failure]`。
- 安装失败提示：`Inspector.tsx` 的 `[data-inspector-install-error]`。
- 引擎状态 / 批量操作 / 任务操作横幅，以及失败筛选的提示带：`App.tsx`，统一为 `border-line bg-raised/60` + `CircleAlert text-clay`。
- 列表行：`TaskRow.tsx` 的状态标签。
- 自动化：`tests/failurePresentation.test.mjs`（源码级规则）、`scripts/qa-workspace.mjs` 的
  `failure details read on the pane surface with one colored mark`（真实计算样式，含浅色主题）。

## 5. 被否掉的方案

| 方案 | 为什么不用 |
| --- | --- |
| 红色底面板（原实现） | 用面积表达紧急度，警报疲劳，正文被降级 |
| 红色左边框 3px 长条 | 比整块底色克制，但边框仍然是一个「色块」；项目里已有过被否决的左侧色条语言 |
| 全中性、不加标记 | 失败状态在长列表里会消失 |
| 徽章 / 胶囊样式 | 普通元数据做成 badge，是同一类模板化处理 |
| 弹出 toast 报错 | 失败是记录的一部分，不是转瞬即逝的事件；toast 关掉后信息就没了 |

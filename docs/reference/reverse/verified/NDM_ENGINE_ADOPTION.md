## 架构决策

保留 Electron/React 界面与独立 Swift NDMHost。Electron 主进程通过异步子进程启动编译好的 host，通过 JSON 行协议通信；打包脚本编译本仓库 host 并将其随 App 分发。用户无需 Swift 开发环境。

这是可长期维护的 macOS 架构，不是必须淘汰的过渡方案。进程边界将网络、存储和 UI 分开；语言本身不保证引擎可靠性，可靠性来自恢复协议、错误处理、进程生命周期和实际验证。Windows 现有单独引擎是维护成本来源；未来若要统一跨平台内核，应由两个平台的需求与兼容测试驱动迁移，不为界面使用 Electron 而重写。

Node 的异步外部程序 API：[child_process.spawn](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options)。Electron 的 utilityProcess 针对 Node 子进程，不是启动 Swift 可执行文件的必选替代品。

## 本轮改动

- 默认仍直接使用用户配置的连接上限（新配置默认 32），不要求打开渐进测速自动调优。
- 先领取待分配段。没有排队段时，空闲槽位可以从最大的未完成尾段接手。
- 自动接手不再取消整轮请求。仅停止所选父段的写入器，等文件关闭后按实际已落盘前缀拆分未写入部分；父段与新子段继续下载，其他请求保持运行。
- 新段表在两段启动前一起原子写入。已有字节不搬移、不截断；保留 segments.bin / seg.xN 续传格式。
- 普通路径不再使用“剩余 75% 活跃连接”的触发门槛。旧的速度/建连成本启发式仅作为显式开启 smartConnections 时的兼容策略保留，不能称为 Neat 原版规则。
- 单个 Range 收到 429/503 时保留其他工作者，读取 Retry-After（秒或 HTTP 日期），最多重试三次；无可用头时采用 1/2/4 秒退避。用户暂停会中断等待。出现服务器拒绝后，本次引擎运行停止继续自动拆分，以免增加请求压力。
- 每次 429/503 将本次运行的请求准入上限保守降低一档；超出的工作者等待槽位，健康请求自然完成，不为降低上限而取消。用户配置保持不变，下次运行重新尝试。这个反馈策略是 NDM 的新增改进，不能称为原版已有功能。
- 详情将用户设置标为“连接上限”，另外显示当前活跃请求及服务器拒绝后的临时上限；没有字节进展时请求数变化也会刷新。此处统计的是 HTTP 请求，不是底层 TCP socket。
- 自动生成的上半段遇到 416 仍走已有回退机制；首次请求的 416 不伪装为成功。

## 明确差异与未改部分

### 32 路中一路完成时

先分配已有排队段；若没有排队段，且没有服务器拒绝、允许自动接手、最大剩余尾段超过 0x3A000 字节，则选它交出未写入尾部。NDM 等该父段写入器关闭，再原子保存缩短后的父段和新子段并启动两者；不取消其余健康请求。因此逻辑活跃数可短暂下降再恢复，累计段数可从 32 增至 33 甚至更多。不能保证每一时刻都有 32 个真实 TCP 连接。尾部很小、服务器拒绝或任务即将结束时不强行补满。

`testThirtyTwoWorkersHandOffAfterFirstCompletionWithoutPause` 使用 16 MiB 固定字节内容、32 路和非均匀响应延迟，不调用暂停；确认初始 32 工作者、新子段 32（第 33 段）、没有整轮重规划、请求数超过 32，最终内容逐字节正确。另有三路测试确认无关范围不会被重请求。

界面按引擎报告的字节位置绘制实际段，不把所有段强制排成 32 格；上方总进度、下方分段进度，另标段数和当前活跃请求数。本轮修复共享动效的比例公式：总体 50% 时完成的段仍应画满，拆分只改变未下载尾部，不挪动已完成的字节区域。普通动画与减少动态效果都要保持同一语义。

Neat 的自有 socket 层和 URLSession 不是同一实现。本轮仍需关闭并重发被拆分的父段；没有声称已做到原请求原地缩短。异常回退或用户主动修改连接数仍可能取消整个计划。

429/503 退避不是精准探测服务器并发上限，也不证明实际 TCP 连接数始终等于配置值。重试耗尽会保存断点并报告失败。

新增受控服务器测试：配置 32 路，服务器最多接受 4 个同时等待响应的 Range 请求；出现拒绝后排队收敛，文件逐字节正确，用户配置仍为 32。429/503 也可能来自限速或临时故障，因此临时上限不跨任务持久化。

HLS 保留独立媒体片段下载与合并路径。Windows 引擎、媒体处理、存储格式和合并方式均未在本轮重写。**合并期间接近双份数据的空间需求仍存在**；单文件偏移写入须另有崩溃、断电、磁盘满与旧任务迁移验证，不能通过修改调度器顺带声称解决。

## 验证范围

集成测试使用独立本地 HTTP 服务器和临时目录，验证：健康范围不被重请求、分段接手后最终字节正确、暂停恢复、手动连接数调整、初始/自动分段 416 区分、Range 不支持回退、429/503 重试及 Retry-After、退避等待中的暂停。核心测试验证单段拆分后的覆盖连续性、前缀保留和其他范围不变。

这些测试不等价于真实 CDN/代理/HTTPS 全场景吞吐基准，也不证明与 Neat 在所有服务器上行为完全一致。

本轮最终验证结果：完整原生测试集通过（815 项 XCTest 中 6 项按配置跳过，另 11 项 Swift Testing 通过）；最终调度代码的 20 项集成测试再次通过。6 项跳过项为显式开启的在线媒体/本机语言模型测试。前端 254 项测试、类型检查、构建及 32 项界面 QA 通过。Release 打包及签名验证通过。使用打包后的可执行文件运行 `qa:task-controls`：连接数调整到达 Swift 引擎、限速、暂停、恢复、完成和清理均通过，renderer 无错误，数据与端口隔离。已部署并启动 `/Applications/NDM.app`。

## 为什么旧导出不能直接照搬

旧脚本的 `decompileCompleted()` 只表示产生文本，不证明语义正确。旧 2,147 个导出中，251 个带有未恢复跳转表警告、41 个带有类型推导警告；不能把这些数量当成错误率。

一个已修复的具体案例：旧输出把 `engine_segment_manager(engine)` 与随后的 `segments_check_all_complete()` 显示成两条独立调用。ARM64 汇编的返回寄存器 x0 实际直接传给后者。修订签名后的 Ghidra 和独立 Hopper 都恢复了管理器参数。HTTP 接手分支的 `segments_have_assignable_work(manager)` 也同样修复。

32 个函数的导出成功仅代表这些产物可用。未解决的虚调用、异常分支、结构体类型仍保留工具警告；没有把它们删掉制造“干净源码”。所有可读函数名均为分析者命名。

## 可依赖的结论

| 结论 | 证据强度 | 地址 / 产物 |
|---|---|---|
| 普通文件的分段分配器先领取已有待分配段，再考虑拆分 | 两个反编译器 + 汇编 | `0x10005e3b8` |
| 拆分候选为剩余数据最多、超过门槛的段；相同最大值保留先遇到者 | 原始机器码执行 | `0x10005e2b4` |
| 普通门槛组：拆分候选严格大于 204,800 B；接手可用性判断存在严格大于 237,568 B 的门槛 | 原始机器码执行 | `0x10005e2b4` / `0x10005e120` |
| 另一个标志分支的门槛为 524,288 / 557,056 B | 原始机器码执行；该标志含义未在本轮完整还原 | 同上 |
| 普通 HTTP 分段完成后存在自动重新排队路径，无须暂停恢复 | 完成回调与虚表/循环静态交叉核对；重新排队决策机器码测试 | `0x100054058` → HTTP 虚表 +0x88 → `0x10003bd14` → `0x100052a30` → `0x1000286fc` |
| 重新排队不是无条件补满；不足门槛的小尾段可以停止接手 | 原始机器码执行 | `0x10003bd14` |
| HLS 按媒体列表建立条目，分配器不走普通文件的二分支路 | 静态交叉核对 | `0x10005ec98` / `0x10005e3b8` 的 manager +0xa8 == 1 分支 |
| HLS 进度按片段编号/总片段数布局，格内按该片段已下载量/大小填充 | 两个反编译器交叉核对 | `0x100008ce8` |
| 普通文件进度按字节偏移布局，与 HLS 的布局含义不同 | 两个反编译器交叉核对 | `0x100008ce8` |
| 合并会读取各段、写入独立输出；复制循环每次读 65,536 B | 静态调用链与 read/write 包装器核对 | `0x10005f66c` / `0x100076b90` / `0x100076d78` |

`0x10005e120` 的接手门槛与 `0x10005e2b4` 的拆分候选门槛不是一个值，不能混写。分配器还有限制段表规模及模式的判断。以上不是“只要少一个连接就立刻新建 TCP 连接”的承诺：socket 对象、HTTP 请求与物理连接也不能混为一谈。

引擎状态通过访问器和主循环对应：1 为 starting，2 为 downloading，5 进入 merging，6 为 completed。socket 状态 0 可再次被调度，7 停止此轮工作。两套状态枚举不能混用。

## 对 NDM 实现的约束

1. 可以参考“完成工作者接下一段”的机制，不能用原版为“取消其他健康请求再整体重分段”背书。
2. 原版自动接手与我们 UI 上的渐进测速/升档自动调优不是同一个概念。
3. 本轮未找到足够证据证明原版有统一的“降到 75% 活跃连接才重分配”规则。不得把我们自己的启发式门槛称作原版常量。
4. HLS 小格数量不是连接数；不要把每个 TS 片段画成一条额外并发连接，也不要据此断言它把同一 TS 再拆成 32 份。
5. 不能从错误分支中的某个 416 回退推广成“所有限流都会自动缩减到服务器允许的连接数”。429/503、认证失败、Range 不支持应分别验证。
6. 原版分段合并设计可参考，但 NDM 可以独立设计单临时文件按偏移写入；这一存储改造需要自己的持久化/崩溃恢复验证。

## 尚未闭环的高风险部分

- 本地 HTTP 的不均匀延迟、连接限制、暂停恢复和 HLS 已完成运行验证，见 RUNTIME.md；HTTPS 和实际 CDN 仍未覆盖。
- 416 回退与父段边界更新的完整并发路径；需进一步修订结构体与虚调用。
- 续传时磁盘长度、段表与服务器文件版本冲突的所有处理分支。
- 磁盘不足/中断合并/清理失败时的完整持久化语义及实际峰值占用。

这些不是已验证事实。本轮保留核心函数产物作为后续入口，没有基于未验证行为改动 NDM 引擎。
